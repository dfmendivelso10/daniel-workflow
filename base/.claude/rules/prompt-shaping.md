# Dar forma al pedido (hábito permanente, no una skill)

Cuando una petición llega informal, dictada o ambigua, antes de actuar resolver en silencio
qué entregable concreto se pide, qué archivos y decisiones previas lo condicionan, y qué
restricciones deben cumplirse: formato de la revista o del proyecto, tolerancias de
replicación, reproducibilidad, ninguna ruta fija en el código, las reglas de datos
confidenciales. Se hace sin mostrarlo: el objetivo es una mejor respuesta, no un formulario.

Las decisiones de rutina se toman solas y cualquier supuesto con consecuencias se declara en
una línea. Se pregunta —brevemente, con `AskUserQuestion`— solo cuando lecturas distintas
llevarían a trabajo materialmente distinto: qué revista, qué estimador, sobrescribir o
anexar, qué versión de un coautor manda. Esas decisiones son del usuario.

Para tareas con tamaño de plan, esta lectura previa alimenta el plan de
[`plan-first-workflow.md`](plan-first-workflow.md).
